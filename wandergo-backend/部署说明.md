# WANDERGO 云服务器部署清单（答辩演示版）

> 目标：给老师一个链接，打开就是**带真实后端的完整系统**（登录、排行、推荐、审核全部有数据库支撑）。
> 全程约 30–60 分钟，费用：学生机 9–24 元/月。

---

## 一、买服务器

| 项目 | 选择 |
|---|---|
| 平台 | 阿里云 / 腾讯云「学生机」或「轻量应用服务器」 |
| 配置 | 2 核 2G，40G 系统盘即可 |
| 系统 | **Ubuntu 22.04 LTS** |
| 地域 | 离你近的（如华东1-杭州） |

买完记下：**公网 IP**、root 密码。

> 用 `http://公网IP` 直接访问不需要备案；想绑域名且服务器在国内才需要 ICP 备案（2–3 周），答辩前来不及就别绑。

---

## 二、开端口（两个地方都要开）

1. **云控制台 → 安全组 / 防火墙**：放行 `80`、`8080`、`22`
2. 服务器内部（Ubuntu 默认 ufw 关闭，若开了则执行）：

```bash
sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 8080
```

---

## 三、装 Docker（一条命令）

SSH 登录服务器后执行：

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
sudo docker compose version     # 显示版本即成功
```

> 国内服务器拉镜像慢，可先配镜像加速：
> `sudo mkdir -p /etc/docker && echo '{"registry-mirrors":["https://docker.mirrors.ustc.edu.cn"]}' | sudo tee /etc/docker/daemon.json && sudo systemctl restart docker`

---

## 四、拉代码并启动

```bash
sudo apt install -y git
git clone https://github.com/TiamEcho/bishe-wandergo.git
cd bishe-wandergo/wandergo-backend

# 可选：改数据库密码（不改则默认 wandergo2026）
sudo MYSQL_ROOT_PASSWORD=你的强密码 docker compose up -d --build
```

首次构建 3–6 分钟，之后 `docker compose up -d` 秒起。

检查三件事：

```bash
sudo docker compose ps                     # 三个容器都是 Up，db 显示 healthy
sudo docker compose logs -f api            # 出现 "Started WandergoApplication"
curl -s http://localhost:8080/api/spot/list | head -c 200   # 返回 JSON 即有数据
```

数据库自动初始化（首次启动时按顺序执行）：
1. `01-wandergo.sql` 建库建表 + 演示账号
2. `02-upgrade_admin.sql` 管理端/评论/点赞升级
3. `03-seed_spots.sql` 爬虫抓取的 5A 景区数据

## 五、验证线上

浏览器打开：

| 地址 | 预期 |
|---|---|
| `http://公网IP/` | 前端首页 |
| `http://公网IP:8080/api/spot/list` | 景点 JSON 数据 |
| `http://公网IP/admin.html` | 管理端（admin / admin123） |

前端会**自动**把接口指向 `http://公网IP:8080`（`js/api.js` 已做自动切换），无需改代码。

如果后端换了端口或用了域名，可在浏览器控制台强制指定：

```js
localStorage.setItem('wgo_api','http://你的地址:8080'); location.reload();
```

## 六、答辩当天演示「后端 + 爬虫」

**后端有真实数据**（投屏给老师看）：

```bash
sudo docker exec -it wandergo-db mysql -uroot -p -e \
  "USE wandergo; SELECT COUNT(*) AS 景点数 FROM t_spot; \
   SELECT COUNT(*) AS 用户数 FROM t_user; \
   SELECT spot_id,name,province,lng,lat,source FROM t_spot LIMIT 5;"
```

**爬虫现场跑**（本机或服务器都行）：

```bash
cd wandergo-crawler
pip install -r requirements.txt
python crawler.py --limit 40 --demo
```

演示模式会打印：
- `[1/3]` 百度百科 5A 名录解析条数
- `[2/3]` 每条景区的详情/坐标来源（`OSM真实坐标` 或 `省会兜底`）
- `[3/3]` 结果汇总表（总数、真实坐标数、省份覆盖、耗时）

跑完把新数据灌进数据库：

```bash
docker exec -i wandergo-db mysql -uroot -p密码 wandergo < wandergo-crawler/seed_spots.sql
```

再回管理端刷新，能看到景点数变化 —— 这就是「真实爬虫 → 真实入库 → 前端可见」的完整闭环。

## 八、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `http://IP/` 打不开 | 安全组没放行 80；或 `docker compose ps` 里 web 没 Up |
| 页面能开但登录失败 | 浏览器 `F12 → Network` 看 `/api/user/login` 是否 502；多半是 api 容器没起来（`docker compose logs api`） |
| 接口 502 / 连不上 8080 | 安全组没放行 8080；或前端在 https 页面请求 http 被混合内容拦截 |
| 容器反复重启 | 内存不足（2G 机器建议 `JAVA_OPTS=-Xmx384m`，在 docker-compose 的 api.environment 里加） |
| 数据库没初始化 | 只在**首次**启动执行；改过 SQL 需 `docker compose down -v` 清卷重来（会丢数据） |
| 中文乱码 | 已配置 `utf8mb4`，若仍乱码检查连接串 `characterEncoding=utf8` |
