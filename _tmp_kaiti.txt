　　随着互联网和在线旅游服务的发展，人们可以通过旅游网站、社交平台和短视频平台获取景点介绍、旅游攻略、交通信息及游客评价等内容。但是，不同类型的旅游信息往往分散在不同页面中，用户在制定旅行计划时，仍然需要自行查找和比较景点、路线、交通及费用等信息。对于第一次前往某个目的地，或者对预算、出行天数和旅游主题有明确要求的用户来说，仅依靠热门景点榜单或通用旅游攻略，可能难以满足实际需要。另一方面，用户在旅游过程中的打卡、评分、收藏和评论能够反映其兴趣偏好，如果这些行为仅用于展示和互动，而没有进一步应用于景点推荐，就难以充分发挥用户行为数据的作用。因此，将旅游攻略查询、个性化推荐与用户打卡分享相结合，具有一定的现实需求。本课题拟设计并实现一个基于Web架构的旅游打卡平台，结合AI需求解析、模块化攻略展示、社区打卡分享和协同过滤推荐等功能，为用户提供更加便捷的旅游信息查询与规划服务。
　　通过整合景点信息查询、旅游攻略规划、打卡分享和个性化推荐等功能，尝试减少用户在不同平台和页面之间反复查找、比较和整理信息的情况。平台将攻略内容划分为景点、路线、交通建议、预算及相关旅行内容等模块，方便用户根据自身需求查看具体信息，并进一步进入相应的详情页面。同时，平台支持用户发布打卡内容、评价和收藏景点，使用户既能够获取旅游信息，也能够记录和分享自己的旅行经历。系统还可以将相关用户行为数据作为推荐算法的输入，为后续的个性化景点推荐提供数据基础，从而使旅游信息获取、旅行体验记录和内容分享形成相互联系的功能体系。
　　系统拟采用Vue、SpringBoot和MySQL等技术完成前端交互、后端业务处理及数据存储，并结合AI需求解析技术，将用户输入的目的地、出行天数、预算和兴趣等信息整理为结构化数据，再按照预先设计的数据结构展示不同类型的旅游攻略。在此基础上，将用户的评分、收藏和打卡记录转化为推荐数据，探索利用协同过滤算法实现个性化景点推荐的方法。通过需求分析、数据库设计、前后端开发、算法实现及系统测试等环节，完成一个能够在浏览器中运行的旅游打卡平台，并通过注册登录、景点查询、攻略展示和打卡互动等功能测试，以及协同过滤推荐与热门景点推荐的结果比较，分析系统的运行情况和推荐算法的适用范围，为后续功能优化和系统改进提供参考。
　　二、 研究现状
　　1. 国外研究现状
　　国外在推荐系统方面开展研究较早，研究内容包括用户行为分析、项目相似度计算和个性化推荐等。Sarwar等人提出了基于项目的协同过滤推荐算法[1]，通过分析用户-项目评分矩阵，计算不同项目之间的相似关系，并利用用户已有的兴趣记录生成推荐结果，为后续推荐系统的设计提供了算法基础。该方法能够利用已有用户行为发现项目之间的联系，为本课题根据用户的景点评分、收藏和打卡记录进行个性化推荐提供参考。相关研究也指出，推荐算法需要考虑数据规模、推荐质量和数据稀疏等问题，用户行为不足时，推荐效果可能受到影响。
　　Jannach等人对推荐系统的发展趋势与研究方向进行了讨论[2]，指出现有研究较多关注推荐算法的改进和离线数据评价，而推荐系统在实际应用中的交互体验及真实使用效果同样值得关注。该研究为本课题从用户需求出发设计个性化推荐功能提供了参考。因此，本系统拟结合用户的收藏、评分及打卡行为，采用协同过滤算法进行景点推荐，并通过模块化卡片展示推荐内容，同时开展功能测试与推荐效果评价，以提高系统的实用性和用户体验。
　　结合本课题的研究方向，国外相关成果主要为个性化推荐和用户行为分析提供了理论参考。但旅游平台还需要结合目的地、出行时间、预算和兴趣等具体条件组织旅游信息，并考虑用户从制定计划到实际打卡、评价和分享的完整过程。因此，本课题将在已有推荐算法研究的基础上，进一步研究推荐功能与旅游攻略展示、社区行为记录之间的联系。
　　2. 国内研究现状
　　国内关于旅游推荐系统和旅游信息网站的研究，主要涉及旅游信息查询、景点推荐、路线规划、用户互动和系统管理等方面。
　　张敏、张腊梅、陈正玉设计了基于Web的旅游推荐系统，采用基于用户的协同过滤方法，并结合景点推荐等功能，根据用户历史行程为用户推荐可能感兴趣的景区[3]。该研究将协同过滤应用于旅游场景，为本课题设计用户行为记录和景点推荐功能提供了参考。不过，该系统采用SSM、JSP等技术，与本课题计划采用的Vue和SpringBoot前后端分离架构有所不同。
　　曹浩、黎杰、谢彬设计了基于SpringBoot和Vue的桂林龙胜各族自治县旅游信息系统，采用前后端分离架构，并提供旅游数据展示、在线地图、旅游攻略和路线规划等功能[4]。该研究与本课题在技术架构和旅游信息组织方面具有较强的关联性，可以为系统模块划分、前后端接口设计和旅游信息展示提供参考。
　　从上述研究可以看出，国内已有研究为旅游信息系统建设、旅游推荐和前后端分离开发提供了基础。但是，不同研究的关注重点有所区别，有的主要关注旅游信息展示和系统管理，有的主要研究推荐算法。对于本课题而言，还需要进一步研究如何将AI需求解析、模块化攻略展示、打卡分享和协同过滤推荐结合起来，并明确用户行为如何转化为推荐数据。
　　三、 存在问题
1. 理论层面
　　(1) 旅游需求的结构化处理问题
　　用户在制定旅行计划时，可能会输入目的地、预算、出行天数和个人兴趣等信息，也可能直接用一段话描述自己的需求。这些信息的表达方式不统一，不方便直接用于系统处理。本课题需要研究如何利用AI提取用户输入中的关键信息，将其整理成统一的数据字段，再结合已有的景点资料和相关规则，把攻略内容划分为景点、路线、交通建议和预算等不同模块。
　　(2) 用户行为数据在景点推荐中的应用问题
　　用户的评分、收藏和打卡记录能够反映一定的兴趣偏好，但这些数据需要经过整理才能用于推荐。本课题计划将用户行为与景点关联起来，根据实际数据选择合适的协同过滤方法，计算用户或景点之间的相似程度，生成Top-N景点推荐列表。对于刚注册、缺少历史行为记录的用户，也需要设计热门景点等基础推荐方式，避免系统无法提供推荐结果。
　　(3) 推荐算法效果的评价问题
　　系统能够生成推荐列表，并不代表推荐结果一定符合用户的兴趣。本课题计划使用具有明确测试条件的用户行为数据，将协同过滤推荐与热门景点推荐进行比较，根据实际数据和测试条件选择合适的评价指标，分析推荐结果的表现，以及算法在不同数据条件下的适用情况。
2. 现实层面
　　(1) 旅游信息分散，查询和整理不够方便
　　用户制定旅行计划时，通常需要在不同网站或平台上查找景点介绍、路线、交通和费用等信息，再自己整理成完整的旅行计划，整个过程比较繁琐。本课题计划将这些信息整合到同一个Web平台中，按照景点、路线、交通建议、预算和相关攻略等内容进行分类展示，用户可以根据自己的需要查看相应模块，也可以进入详情页面了解具体信息。对于没有可靠来源支持的价格、交通等内容，系统会标注为示例或待核实信息，避免将未经确认的内容直接当作真实信息展示。
　　(2) 旅游打卡和分享功能的利用不够充分
　　用户在旅行过程中会留下打卡、评分、收藏和评论等记录，这些内容不仅可以用于分享旅行经历，也能为后续的景点推荐提供参考。如果相关数据只用于社区展示，没有进一步应用于用户兴趣分析，就难以发挥其作用。本课题计划实现打卡发布、评分、收藏和评论等功能，并通过数据库保存用户行为及其关联的景点信息，为推荐模块提供相应的数据支持。
　　(3) 个性化推荐与用户实际需求的结合问题
　　不同用户的旅游兴趣和出行偏好存在差异，仅按照景点热度进行推荐，可能无法满足所有用户的需求。本课题计划根据用户已有的评分、收藏和打卡记录生成个性化景点推荐，并为缺少历史行为的新用户提供基础推荐。系统完成后，将通过功能测试和推荐效果测试，检查用户操作、数据保存和推荐结果之间的联系是否正常，分析系统在实际使用场景中的表现。研究目标和内容　　一、 研究目标
1. 总体目标
　　本课题旨在设计并实现一个基于Vue、SpringBoot和MySQL的旅游打卡平台，将AI需求解析、模块化旅游攻略展示、用户打卡分享和协同过滤推荐相结合，构建集旅游信息查询、攻略规划、旅行记录和个性化推荐于一体的Web应用系统。通过前后端协同开发、数据库设计和推荐算法实现，完成从旅游需求输入、攻略内容查看、社区互动到景点个性化推荐的基本业务流程，并通过系统测试分析平台的功能实现情况及推荐算法的应用效果。
2. 具体目标
　　(1) 完成旅游打卡平台的需求分析与总体设计，明确不同用户角色的功能权限，确定系统架构、主要功能模块、核心业务流程和数据库设计方案，为系统开发提供完整的设计依据。
　　(2) 实现基于AI需求解析的旅游攻略展示功能，使系统能够识别用户的目的地、出行天数、预算和兴趣等需求，并结合已有旅游数据，将攻略内容组织为景点、路线、交通建议、预算及相关攻略等模块，方便用户查询和查看详细信息。
　　(3) 实现用户注册登录、景点浏览、图文打卡、评分、收藏、评论、个人足迹和个人中心等核心功能，建立用户、景点与旅行记录之间的关联，使用户能够完成旅游信息查询、旅行经历记录及社区互动等操作。
　　(4) 实现基于用户行为数据的协同过滤推荐功能，将评分、收藏和打卡等行为用于用户兴趣分析，生成个性化景点推荐结果，并针对历史行为不足的新用户提供基础推荐方案，使旅游打卡数据能够进一步应用于景点推荐。
　　(5) 完成系统功能、接口和推荐效果测试，检查主要业务流程及数据处理是否符合设计要求，并通过与热门景点推荐结果进行比较，分析协同过滤算法在测试数据中的表现、适用条件及现有不足，为后续系统优化提供依据。
　　二、 研究内容
　　1. 前端页面与交互设计
　　前端采用Vue构建浏览器端Web页面，围绕用户旅游计划和旅行分享的使用流程进行设计。
　　用户端主要包括注册登录、首页、目的地和景点浏览、旅游攻略需求输入、攻略模块化展示、景点详情、社区打卡、评分收藏、评论互动、个人足迹和个人中心等功能。攻略展示页面将景点、路线、交通建议、预算及相关攻略内容分别组织成模块，用户可以点击相应模块查看详细信息。
　　前端还需要处理表单校验、加载状态、无查询结果、请求失败等情况，并通过HTTP接口与后端交换数据。管理端主要提供景点资料维护、用户管理和内容审核等界面。
　　2. 后端业务服务设计与实现
　　后端采用Java和SpringBoot构建业务服务，按照用户管理、景点信息、攻略服务、社区互动、推荐服务和后台管理等功能划分模块[5]。
　　后端负责处理前端提交的请求，完成参数校验、权限检查、业务规则处理和数据库访问。用户提交旅游需求后，后端调用需求解析模块，获取目的地、出行天数、预算和兴趣等字段，再结合数据库中的景点信息和预设规则组织攻略结果。
　　在用户发布打卡、评分、收藏和评论时，后端需要检查用户身份和相关数据的有效性，并保存操作记录。推荐模块读取用户行为数据后，计算景点推荐结果并返回前端。
　　3. 数据库设计与数据管理
　　本课题采用MySQL保存系统运行所需的数据，主要包括用户、景点、景点类别、攻略、行程节点、打卡记录、评分记录、收藏记录、评论和用户行为等数据。
　　设计数据库时，需要明确各个数据表的字段、主键、外键和关联关系。例如，用户表保存用户基本信息，景点表保存景点名称、地区、类别、简介和数据来源，打卡表保存用户发布的内容及其关联景点，行为记录表保存用户对景点的评分、收藏和打卡等行为。
　　通过数据库设计，使旅游信息能够被查询和维护，用户的社区行为也能够被推荐模块读取。对于公开数据和人工整理的数据，应记录相应来源及整理规则；用于演示的构造数据应明确标注为测试数据。
　　4. AI需求解析与模块化攻略展示
　　本课题拟研究AI在旅游需求整理和攻略内容组织中的应用，而不是仅仅通过AI生成一段完整的旅游介绍。
　　用户可以通过表单或简短自然语言输入目的地、出行天数、预算和兴趣等条件。系统将这些信息提交给需求解析模块，由AI提取相应字段，再由后端检查字段是否完整、格式是否符合要求。通过校验后，系统根据已有景点资料和预设规则组织攻略内容。
　　攻略结果采用结构化数据返回前端，按照景点推荐、路线安排、交通建议、预算分项和相关攻略等模块展示。用户可以分别查看各个模块的详细内容，从而减少长篇文本中信息查找不便的问题。
　　需要注意的是，AI主要承担需求提取和内容组织工作。景点推荐排序由推荐算法或明确的业务规则负责；对于没有可靠来源支持的票价、交通班次和开放时间，不将AI生成结果直接当作实时事实。
　　5. 协同过滤推荐算法设计与实现
　　本课题拟利用用户的评分、收藏和打卡行为建立用户-景点偏好数据，为个性化景点推荐提供依据。
　　首先，根据系统记录的用户行为，明确不同类型行为的处理规则，将相关记录转化为用户对景点的偏好数据。其次，根据实际数据规模选择基于用户或基于项目的协同过滤方法，计算用户或景点之间的相似关系，并筛选用户尚未访问或尚未产生相关行为的候选景点。最后，按照计算结果生成Top-N推荐列表，并将结果返回前端展示。
　　对于缺少历史行为的新用户，系统使用热门景点或用户主动选择的兴趣类别作为基础推荐方式。后续用户产生新的打卡、评分和收藏记录时，系统将保存这些行为，供推荐模块在之后的请求中使用。
　　6. 系统测试与推荐效果评价
　　系统完成后，开展功能测试、接口测试和推荐效果测试。
　　功能测试主要检查注册登录、景点浏览、攻略需求输入、模块化结果展示、打卡发布、评分收藏、评论、个人中心和管理端等功能是否符合设计要求。接口测试重点检查参数错误、未登录访问、权限不足和重复操作等情况。
　　推荐效果测试将使用具有明确兴趣偏好的测试账号和相应行为数据，比较协同过滤推荐结果与热门景点推荐结果。根据测试数据和评价条件，选择Precision@K、Recall@K或命中率等指标进行分析，同时记录数据规模、测试过程和实际结果。
　　通过上述测试，分析系统是否完成预期功能，以及推荐算法在不同数据条件下的表现，不预先假定协同过滤一定优于热门推荐。研究方法、步骤和措施　　一、 研究方法
1. 文献研究法
　　本课题围绕旅游信息系统、旅游推荐系统、协同过滤算法、人工智能辅助旅游规划、Web 前后端分离架构等方向开展文献研究，为系统功能设计、技术选型和推荐算法实现提供理论依据。
2. 需求分析法
　　本课题以用户从发现旅游目的地、制定出行计划，到记录旅行经历并分享给其他用户的完整过程为分析对象，结合现有 HTML 网页原型梳理系统功能，进一步明确不同用户角色的需求、业务流程和数据处理要求。
3. 系统设计与实现法
　　本课题采用前后端分离的 Web 系统开发方式，使用 Vue 实现页面展示和交互，使用 Spring Boot 实现后端业务服务，使用 MySQL 保存用户、景点、攻略、打卡及行为记录等数据。开发过程中以现有 HTML 网页原型作为界面和功能需求参考，将原型中的交互设计逐步转化为可与后端接口和数据库配合运行的系统功能。
　　攻略数据返回、打卡发布、评分收藏、评论和推荐结果获取等功能。使用 MySQL 设计用户表、景点表、攻略表、行程节点表、打卡表、评分表、收藏表、评论表及用户行为记录表等，并明确主要字段和关联关系。用户发布打卡或进行收藏、评分等操作时，后端应完成必要的身份校验和数据校验，再保存对应记录，供个人中心、社区页面及推荐模块读取。
4. 算法实验法
　　本课题以用户对旅游景点的兴趣偏好为研究对象，重点研究如何将打卡、评分和收藏等社区行为转化为推荐依据，并将协同过滤推荐结果接入网页中的景点推荐区域。算法实验主要用于验证推荐流程能否正常运行，以及推荐结果在设定的测试条件下是否与用户兴趣相符。
5. 功能与接口测试法
　　本课题通过功能测试、接口测试和推荐效果测试检查系统实现情况，重点验证网页原型中的主要功能是否转化为能够实际运行的业务流程，以及用户操作产生的数据能否在相关页面和推荐模块中得到正确使用。
　　二、 研究步骤和措施
　　研究步骤与措施
　　第一阶段：需求分析与文献整理
　　结合旅游攻略查询、旅行规划、打卡分享和个性化推荐等实际场景，明确系统的目标用户、主要功能和拟解决的问题。
　　围绕旅游推荐系统、协同过滤算法和Vue、SpringBoot旅游信息系统等主题查阅相关文献，整理国内外研究现状，核对参考文献的基本信息，明确本课题与已有研究的联系和区别。
　　阶段成果：需求分析材料、研究现状初稿、功能清单和参考文献目录。
　　第二阶段：系统总体设计与数据库建模
　　根据需求分析结果，确定系统总体架构、功能模块和前后端职责，绘制系统架构图、功能模块图和主要业务流程图。
　　根据用户、景点、攻略、行程节点、打卡、评分、收藏、评论和行为记录等业务，设计MySQL数据表，明确主要字段、主外键关系和数据关联方式，并绘制E-R图。
　　阶段成果：系统总体设计方案、功能模块图、业务流程图、E-R图和数据库表结构。
　　第三阶段：前后端基础功能开发
　　搭建Vue、SpringBoot和MySQL开发环境，完成前端页面框架、后端接口和数据库连接。
　　优先实现用户注册登录、景点列表与详情、旅游需求输入、攻略模块化展示和个人中心等基础功能；随后完成打卡发布、评分收藏、评论互动和后台信息维护。开发过程中通过接口联调，检查数据能否正确传递、保存和读取。
　　阶段成果：可运行的基础Web系统，以及主要业务模块的初步实现。
　　第四阶段：AI需求解析与推荐算法集成
　　明确AI需求解析模块的输入字段和输出结构，实现目的地、出行天数、预算和兴趣等信息的提取、校验和缺失信息提示。
　　在此基础上，读取数据库中的景点信息并组织模块化攻略内容。同时，将用户的评分、收藏和打卡记录转化为推荐数据，完成协同过滤算法中的相似度计算、候选景点筛选和Top-N排序，并为新用户设置基础推荐策略。
　　阶段成果：AI需求解析与模块化攻略功能，以及可以接入前端页面的景点推荐模块。
　　第五阶段：系统测试、效果分析与论文完善
　　根据功能需求完成注册登录、景点查询、攻略展示、打卡互动、推荐服务和管理端等功能测试，检查异常参数、权限控制和数据保存等情况。
　　构建具有明确兴趣偏好的测试账号，将协同过滤推荐结果与热门景点推荐结果进行比较，记录相应评价指标和测试过程。根据测试结果整理系统运行情况、推荐效果和存在的不足，完成论文修改、系统演示材料和答辩准备。
